# Phase 2-4 除外設定 手動確認項目

## 設定画面

1. 「アクセス解析」配下に「設定」が表示されることを確認する。
2. 解析画面上部の「設定」ボタンから同じ画面を開けることを確認する。
3. 管理権限を持たないユーザーが設定画面と保存処理を利用できないことを確認する。
4. nonceがない、または正しくない保存リクエストが拒否されることを確認する。
5. 保存後に成功通知が表示され、選択内容が維持されることを確認する。

## 計測ON・OFF

1. 初期状態で解析画面上部に「計測中」と表示されることを確認する。
2. 「アクセス解析を計測する」をOFFにし、公開ページへ計測スクリプトが読み込まれないことを確認する。
3. キャッシュに古い計測スクリプトが残っていても収集APIが記録を受け付けないことを確認する。
4. OFFの間も既存の解析データを閲覧できることを確認する。
5. ONへ戻すと新しい訪問から計測が再開することを確認する。

## ログインユーザー除外

1. 初期状態で管理者が除外されていることを確認する。
2. 編集者など別の権限を選択し、そのユーザーによる公開ページ閲覧が集計されないことを確認する。
3. 除外を解除した権限の閲覧が新しい訪問として集計されることを確認する。
4. 複数の権限を持つユーザーは、いずれか1つが除外対象なら計測されないことを確認する。

## IP除外

1. 正しいIPv4を追加し、登録後は末尾が`xxx`のマスク表示になることを確認する。
2. 正しいIPv6を追加し、省略されたマスク表示になることを確認する。
3. 同じIPv4・IPv6を表記違いで追加しても重複登録されないことを確認する。
4. 不正なIP、CIDR形式、IP以外の文字列が追加されず警告件数へ表示されることを確認する。
5. 登録済みIPからの公開ページ閲覧がPV・訪問へ含まれないことを確認する。
6. 削除へチェックして保存すると、該当IPの除外が解除されることを確認する。
7. WordPressオプションには生のIPではなく、64文字のハッシュとマスク表示だけが保存されることを確認する。
8. 最大50件を超えてIPが保存されないことを確認する。

## CDN・プロキシ

1. 通常環境では現在の接続元IPと「このIPを除外へ追加」が表示されることを確認する。
2. Cloudflareやリバースプロキシのヘッダーを検出した場合、ワンクリック追加が停止して警告が表示されることを確認する。
3. Cloudflareの実IPを信頼する構成では、サーバー管理者が`AAP_TRUST_CF_CONNECTING_IP`を明示した場合だけヘッダーを利用することを確認する。
4. プロキシ全体のIPを誤登録して一般訪問をまとめて除外しないことを確認する。

## Bot判定

1. Googlebot、Bingbotなど既知クローラーが除外されることを確認する。
2. GPTBot、ClaudeBot、PerplexityBotなどAIクローラーが除外されることを確認する。
3. Semrush、Ahrefs、Screaming FrogなどSEO検査ツールが除外されることを確認する。
4. UptimeRobot、Pingdomなど監視サービスが除外されることを確認する。
5. 一般的なPC・スマートフォンのUser-Agentが誤ってBot扱いされないことを確認する。

## 除外件数

1. 解析画面下部に「この期間に除外したアクセス」と合計件数が表示されることを確認する。
2. 展開するとBot、ログインユーザー、IP除外、異常な連続送信、外部送信の内訳が表示されることを確認する。
3. 今日、昨日、7日、30日、今月、期間指定と日付移動に件数が連動することを確認する。
4. Phase 1で保存された`administrator`除外が「ログインユーザー」へ統合表示されることを確認する。

## 保存期間・アンインストール

1. 保存期間を30、60、90、180、365日から選択して保存できることを確認する。
2. 日次クリーンアップが選択した期間より古い詳細データを削除することを確認する。
3. 「プラグイン削除時に解析データも削除する」が初期OFFであることを確認する。
4. OFFで削除した場合は解析テーブルを残し、専用権限だけ削除することを確認する。
5. ONで削除した場合は解析テーブル、設定オプション、専用権限が削除されることを確認する。

## 既存機能

1. Phase 2-1の有効閲覧時間が従来どおり保存されることを確認する。
2. Phase 2-2の平均閲覧時間・直帰率・1訪問あたりPVが従来どおり表示されることを確認する。
3. Phase 2-3のデバイス比率が従来どおり表示されることを確認する。
4. WordPressダッシュボードウィジェットの表示速度と簡潔さが大きく変わらないことを確認する。
