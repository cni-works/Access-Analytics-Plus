# Phase 2-5 実サイト受入テスト

対象Build: `phase2-5-ui4.20260828.1`

## 導入直後

1. プラグインを更新する。
2. キャッシュプラグイン、CDN、ブラウザーのキャッシュを消す。
3. アクセス解析 → 設定の最下部が `Build phase2-5-ui4.20260828.1` であることを確認する。
4. PHPエラーログにWarning、Notice、Deprecatedがないことを確認する。
5. 既存の訪問者、PV、有効閲覧時間、除外設定が残っていることを確認する。

## キャッシュ環境

各製品は同時に重ねず、実際に採用する構成ごとに確認する。

1. 未ログインの別ブラウザーで公開ページを開く。
2. 開発者ツールのNetworkで `/wp-json/access-analytics-plus/v1/collect` がPOSTされ、201または除外時202になることを確認する。
3. 15秒以上表示し、`/engagement` がPOSTされることを確認する。
4. 公開ページを再読み込みし、PVが1だけ増えることを確認する。
5. 管理者で同じページを見て、PVが増えず除外件数だけが増えることを確認する。
6. 管理画面を再表示し、最大30秒以内に新しい数値になることを確認する。

製品別補足:

- WP Fastest Cache: 計測scriptに `data-cfasync="false"` と `data-wpfc-render="false"` があることを確認する。
- LiteSpeed Cache: JS遅延を有効にしてもtracker.jsが即時実行されることを確認する。必要ならJS除外欄にも `access-analytics-plus/assets/js/tracker.js` を追加する。
- Autoptimize / Autoptimize Pro: 「すべてのJSを遅延」時はtracker.jsを除外し、操作しない訪問でもPVが記録されることを確認する。
- Cloudflare: `/wp-json/access-analytics-plus/v1/*` をCache Everything対象にしない。Rocket Loader有効時もtracker.jsに `data-cfasync="false"` があることを確認する。

## 複数タブ

1. 同じブラウザーで公開ページを2タブ同時に開く。
2. PVは開いたページ数だけ増え、訪問が2件に分裂しないことを確認する。
3. 片方を前面、片方を背面にして2分待つ。
4. 背面タブの有効閲覧時間が増えていないことを確認する。
5. タブを切り替え、前面になったタブの時間が再開することを確認する。
6. 同じ滞在時間送信を再試行しても秒数が倍にならないことを確認する。

## iPhone Safari / Android Chrome

1. 今日、昨日、7日、30日、今月、期間指定を順にタップする。
2. 昨日から前の日へ2回進み、次の日で戻れることを確認する。
3. グラフの1日をタップし、その日だけの表示になることを確認する。
4. 画面幅を超える横スクロールがないことを確認する。
5. 期間ボタンと日付矢印を片手で誤操作なく押せることを確認する。
6. 公開ページを30秒表示し、別アプリへ2分切り替え、戻って30秒表示する。有効時間がおおむね60秒であり、180秒にならないことを確認する。
7. 戻る・進むで復帰しても時間が急増しないことを確認する。

## 期間連動

各期間で次が同じ開始日・終了日の条件に変わることを確認する。

- 訪問者
- PV
- 平均閲覧時間
- 直帰率
- 1訪問あたりPV
- 流入元
- 人気ページ
- デバイス
- 除外件数

今日と直近30分を含む直帰率は暫定値になること、終了訪問がない場合はデータなしになることも確認する。

## 保存期間

ステージングで90日より古い詳細テストデータを用意する。

1. `aap_daily_cleanup` を実行する。
2. 1回で25,000件を超える削除が必要な場合、複数回に分かれることを確認する。
3. 90日より古いpageviews、sessions、ユニーク判定マーカーが削除されることを確認する。
4. `aap_daily` と `aap_exclusions_daily` が残ることを確認する。
5. 過去の日次グラフが壊れず、最大90日の詳細レポートが欠損しないことを確認する。

## ダッシュボード

1. WordPressへログイン直後のダッシュボード表示時間を確認する。
2. ウィジェットには今日の訪問者、PV、7日推移、今月訪問者、人気ページだけが表示されることを確認する。
3. 専用解析画面と同時に開いてもPHPエラーやタイムアウトがないことを確認する。
4. 「詳しいアクセス解析を見る」で専用ページへ移動できることを確認する。

## 合格後

結果を `phase-2-5-quality-report.md` の残る受入確認へ追記する。Search Console・地域判定などの次フェーズへは自動で進まない。
