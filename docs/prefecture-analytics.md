# 日本国内の都道府県別アクセス分析

## 集計定義

- 対象は、国判定が `JP` となり、閲覧信号によって `confirmed` へ昇格したアクセスだけ。
- 指標はページビュー数ではなく、選択期間内の一意な訪問者数。
- 同じ訪問者に複数セッションがある場合、その期間内で最初にconfirmedとして作成されたセッションの `region_code` へ1回だけ割り当てる。
- 都道府県を判定できない日本国内アクセスは「判定不能」として分母・内訳に含める。
- 機能導入前の既存セッションは推測で補完せず、`aap_region_tracking_started_at` 以降だけを集計する。

携帯回線、VPN、企業ネットワーク、ISPの出口拠点等により、推定都道府県は利用者の実際の所在地と異なることがある。

## 判定経路

1. `Country_Resolver` で国を判定する。
2. 国が `JP` でない場合、都道府県照合を行わない。
3. `aap_region_code` フィルター、信頼済みCloudflare、信頼済みサーバーGeoIP、更新MMDB、同梱MMDBの順で照合する。
4. collect時は `aap_shadow_events` に候補を保存する。
5. confirmed昇格時、新規セッションへ `country_code` と `region_code` を固定する。ページビュー表へ地域列は持たせない。

生IPはHTTPリクエスト処理中の国・都道府県照合にだけ使用し、解析テーブルへ保存しない。

## 同梱データ

- ファイル: `data/aap-japan-prefecture-2026-09.mmdb`
- 元データ: DB-IP City Lite 2026-09（CC BY 4.0）
- 派生処理: 日本のみ抽出、都道府県を `JP-01`〜`JP-47` へ正規化、同一コードの連続範囲を統合、不要フィールドを削除
- MMDBの値: `region_code` のみ
- 配布物の詳細と帰属: `THIRD_PARTY_NOTICES.md`

`tools/build-prefecture-mmdb.py` は中間CSV.GZのSHA-256、範囲順序、重複、47コード、IPv4/IPv6代表値を検査してMMDBを生成する。元のCity Lite全量データはRepositoryや配布ZIPへ含めない。

## 更新基盤

都道府県データはプラグイン本体とは別の専用フィードを将来設定できる。初期状態では外部フィードURLを持たず、更新ボタンは無効である。

フィードを設定する場合はHTTPSのmanifestを使用し、版、CC BY 4.0表記、容量、SHA-256、MMDBメタデータ、国内・国外プローブを検証してから、hash入りファイル名で `wp-content/uploads/access-analytics-plus/geo/` へ保存する。状態切替後に旧更新ファイルを削除するため、失敗時は既存更新データまたは同梱データへ戻る。

設定方法:

- 定数 `AAP_REGION_DATABASE_MANIFEST_URL`
- フィルター `aap_region_database_manifest_url`

更新フィードの公開、Repository作成、署名・配信運用は本実装の対象外。

## 手動確認

1. DB Version 9への更新後、設定画面で都道府県DBの版・状態・帰属を確認する。
2. 未ログインの日本国内回線から3秒以上表示または操作し、confirmedへ昇格させる。
3. 選択期間の「アクセス地域（推定）」に一意な訪問者として反映されることを確認する。
4. 同じブラウザーで複数ページを閲覧しても都道府県の人数がPV数に応じて増えないことを確認する。
5. 期間を変更すると内訳が連動し、導入開始日を含む期間では一部期間である旨が表示されることを確認する。
